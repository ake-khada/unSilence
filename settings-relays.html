Settings & Relays · redesign · Claude Code handoff

Make the plumbing
feel effortless.

Relays are unSilence's superpower and its steepest cliff. The current Settings and Relay screens expose raw protocol mechanics — overflowing tabs, contradictory health signals, cryptic R/W boxes, one-tap deletes — with no way to discover relays or understand what one actually is. This redesign keeps every capability, applies the AMOLED + golden-ratio system, fixes the navigation, and adds the two missing surfaces: a relay discovery browser and a per-relay detail page.

  • 1
    Tabs overflow & cut off
    Six tabs scroll horizontally; "Blocked" is sliced to "Blo…" with no signal there's more. Add a right-edge fade, leading icons, and a filled active pill so it reads as a scrollable rail — not a broken header.
  • 2
    Categories are unexplained jargon
    "Inbox/Outbox", "Index", "Search" are NIP-65 terms. Most users have no idea what each list controls. Show a one-line description + relay count for the active category directly beneath the rail.
  • 3
    Health signals contradict each other
    A green status dot beside red "520ms" says "healthy" and "broken" at once. Unify: the dot colour is the latency tier, and the latency text matches it (mint/amber/rose). One coherent signal.
  • 4
    "R/W" box & one-tap delete
    The cryptic teal "R/W" gives no read of state, and the trash icon nukes a relay in one tap. Split into two labelled R / W toggle pills, and move removal behind a swipe (or the detail page) with confirm.

Relay row, decoded

One row, five jobs — each legible at a glance, none cryptic. Built unboxed with a hairline separator, matching the Feed.

① Health dot
Colour = latency tier. Mint (fast), amber (slow), rose (offline). Pulses softly while a ping is in flight. This is the only health signal — no more dot/latency contradiction.
② Host name
The wss:// is stripped for scannability; the full URL lives on the detail page. 13–15sp, text-1, weight 500.
③ Meta line
Qualitative + precise. "fast · 113 ms" tells a newcomer and a power user at once. Optional NIP highlight (e.g. "NIP-50 search") when relevant. Mono, tier-coloured.
④ R / W pills
Two independent toggles. Filled cyan = enabled, ghost = disabled. You can see at a glance that a relay is read-only. Replaces the opaque "R/W" box.
⑤ Chevron / swipe
Tap the row → detail page. Swipe left reveals a deliberate red "Remove" — no more accidental one-tap deletes. Removal also lives in the detail page with a confirm.

File
ui/screens/RelayDetailScreen.kt
Source
Fetch the relay's NIP-11 document (GET with Accept: application/nostr+json) for name, description, supported_nips, software, pubkey, limitation/payments_url. Cache it; show skeletons while loading.
Hero
50dp rounded operator icon (NIP-11 icon or generated), host name in display 18sp, full wss:// URL in mono with a copy button.
Stats strip
Four cells: live latency (tier-coloured), 30-day uptime, NIP count, "N you follow". Cells are dividers of border-faint on elev-1.
Sparkline
24h latency history as a filled line chart (tier colour). Sampled from periodic pings stored locally. Hide if no history yet.
Features
NIP chips; highlight the meaningful ones (Search, Outbox, Auth) in brand, the rest neutral, with a "+N" overflow that expands.
Policy
Key/value rows: payment (Free / "8k sats" in zap colour), auth required, software+version, operator contact (tappable npub).
Actions
Sticky footer. Primary cycles membership state: "Add to my relays" → "Read & write ✓" → tap opens R/W editor. Star = favorite. Rose ⊘ = block (confirm). Overflow (⋯) = copy URL, open in browser, share, remove.
